How data gets from Fabric to the dashboard

The executive signs in with Microsoft Entra ID and calls our own API. One custom container on Azure App Service hosts the React site and the ASP.NET Core API. The API reads approved KPI outputs from the Fabric gold layer as the App Service managed identity, so no secret is stored anywhere. The browser never holds a Fabric credential.

Executive journey, as built

Each step and where it lives in the code.

  1. Open the dashboard.App Service serves the React build from wwwroot. The site first loads /api/client-config, which holds only the public tenant ID, client ID and scope, so one build works in Dev, UAT and Production.
  2. Sign in with Microsoft Entra ID.MSAL React uses the authorization code flow with PKCE. Tenant policies such as MFA and Conditional Access apply. frontend/src/auth/
  3. Acquire an API access token.The token is requested for api://…/Dashboard.Read and is sent only to this API. The browser has no secret and no Fabric credential.
  4. Request dashboard data.GET /api/v1/vas/revenue?from=2026-01&to=2026-09&country=UAE over HTTPS with the bearer token.
  5. Validate and authorise.The API checks signature, issuer, audience and expiry, then requires the Dashboard.Read scope and the Dashboard.Viewer role. Filters are checked for format and against known countries, centres and visa types. A filter only narrows results; it never grants access. Security/, Reporting/ReportFilter.cs
  6. Authenticate the backend to Fabric.Azure.Identity obtains a token for the App Service managed identity and Microsoft.Data.SqlClient connects with it. No secret is stored and there is no Key Vault. The executive's token is never reused.
  7. Query approved reporting outputs.The API runs one parameterised, read-only query per KPI, embedded in the build. Connections are pooled, and tokens are renewed automatically. Reporting/Sql/
  8. Return dashboard-ready results.The response is { data, meta }: KPI values, previous-period comparisons, statuses and breakdowns, currency, time zone, last gold refresh, applied filters and a correlation ID. All formulas run in KpiService, so React does no KPI maths.
  9. Render the premium experience.The site shows animated cards, charts and a 3D revenue view, with loading, empty, error and "out of date" states. Changing a filter repeats the request.
  10. Refresh source data independently.The existing VAS ingestion refreshes the gold layer on its own schedule. Reloading the page never triggers ingestion.

Security built in

What protects the data path.

Two separate identitiesThe executive token authorises calls to our API. The managed identity authorises the Fabric SQL connection. They are never swapped, and neither involves a stored secret.
Rejected callers are testedTests cover a missing token, garbage, expired, wrong audience, wrong issuer, wrong signing key, missing or wrong scope, and a missing role.
Least privilege on FabricThe API uses a read-only connection intent and SELECT on the reporting views only. Queries ship inside the assembly.
Safe failuresErrors are ProblemDetails with a correlation ID and no stack traces. A Fabric outage returns 503 and fails the readiness check, while the liveness check used by App Service stays healthy.
Hardened originHTTPS with HSTS, a strict CSP that allows only this site and Entra, no-store on API responses, and per-user rate limiting.
Development shortcuts are lockedSample data and the sign-in bypass refuse to start outside Development.
